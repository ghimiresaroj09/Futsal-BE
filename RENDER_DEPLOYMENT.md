# Render deployment — complete, self-contained guide

**Part A** = what *you* click in dashboards. **Part B** = the complete file
changelist for the agent in the fresh workspace. Part B assumes **nothing** has
been added yet: every file and every edit is listed in full, in dependency order.

Prerequisites you already have: **Neon** (Postgres) and **Redis**.

---

## Architecture on Render's free plan

```
Render free web service  →  Django + gunicorn   ($0, sleeps after 15 min idle)
Neon                     →  Postgres            ($0, does not expire)
Redis                    →  Django cache        ($0)
Cloudinary               →  images + video      ($0)
cron-job.org             →  reminder trigger    ($0, also keeps the app awake)
```

**Two limits to design around.**

1. **Free services sleep after 15 minutes of inactivity**, then take 30-60s to
   wake. The external cron below pings every 10 minutes, which keeps the service
   warm *and* drives reminders — one free job solving both problems.
2. **Render background workers have no free tier**, so Celery Beat cannot run.
   Reminders are dispatched by an HTTP endpoint instead. The Celery code is left
   untouched and still works the moment you move to a paid worker.

## Step 1. Get your Neon connection string

Neon dashboard → **Connection Details** → copy the **pooled** string (its host
contains `-pooler`):

```
postgresql://user:pass@ep-xxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
```

## Step 7. Schedule the reminder cron

Render's free plan has no cron jobs, so use an external pinger. This also keeps
the service awake.

1. Sign up at **cron-job.org** (free)
2. **Create cronjob**:
   - URL: `https://futsal-api.onrender.com/api/v1/internal/cron/reminders/`
   - Schedule: every **10 minutes**
   - Headers → `Authorization: Bearer <your CRON_SECRET>`
3. Save, then **Run now** and confirm a 200

Check by hand:

```bash
curl -H "Authorization: Bearer $CRON_SECRET" \
  https://futsal-api.onrender.com/api/v1/internal/cron/reminders/
# {"success":true,"message":"Reminder dispatch completed.","data":{"sent":0,"failed":0}}
```

Without the header it must return **401**.

At $7/mo per worker, uncomment the two `worker` blocks in `render.yaml` and
redeploy — then **delete the external cron job**, or reminders fire twice.
No code changes are needed.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Build: `permission denied` | script not executable | `git update-index --chmod=+x render_build.sh` |
| `DisallowedHost` | host missing | add `.onrender.com` to `ALLOWED_HOSTS` |
| Deploy rolls back | health check failing | check `/healthz/` and `DATABASE_URL` |
| Swagger unstyled | `collectstatic` skipped | check build log; WhiteNoise must be in `MIDDLEWARE` |
| First request takes 60s | free tier asleep | expected; the 10-min cron keeps it warm |
| `too many connections` | direct DB string | use Neon's **pooled** string |
| `DB index is out of range` | `/1` on Redis URL | remove the suffix |
| Cron 401 | secret mismatch | compare `CRON_SECRET` with the header |
| Uploads 500 | Cloudinary creds missing | disk is ephemeral; Cloudinary is required |

Logs: Render dashboard → service → **Logs**.

## 3. `config/settings/production.py` — REPLACE

Full contents:

```python
"""Production settings."""
from .base import *  # noqa: F401,F403
from .base import config, Csv

DEBUG = False
ALLOWED_HOSTS = config("ALLOWED_HOSTS", default="", cast=Csv())

# --- serverless / proxy hosts ----------------------------------------------
# The app runs behind the platform proxy (*.onrender.com). CSRF needs the
# scheme-qualified origin, which ALLOWED_HOSTS does not cover.
CSRF_TRUSTED_ORIGINS = config(
    "CSRF_TRUSTED_ORIGINS",
    default="https://*.onrender.com",
    cast=Csv(),
)

# --- static files -----------------------------------------------------------
# No nginx sits in front of gunicorn, so Django must serve its own
# static assets (Swagger UI / DRF browsable API CSS). WhiteNoise does that.
MIDDLEWARE = [
    m for m in MIDDLEWARE  # noqa: F405
    if m != "whitenoise.middleware.WhiteNoiseMiddleware"
]
MIDDLEWARE.insert(
    MIDDLEWARE.index("django.middleware.security.SecurityMiddleware") + 1,
    "whitenoise.middleware.WhiteNoiseMiddleware",
)
STORAGES = {
    **STORAGES,  # noqa: F405  (keeps the Cloudinary default from base.py)
    "staticfiles": {
        "BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage"
    },
}

# Render/most PaaS already terminate TLS and redirect; a second redirect in the app
# causes a loop, so this defaults off (set SECURE_SSL_REDIRECT=True on
# hosts that need Django to do the redirecting).
SECURE_SSL_REDIRECT = config("SECURE_SSL_REDIRECT", default=False, cast=bool)
SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
SECURE_HSTS_SECONDS = 60 * 60 * 24 * 30
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True
SECURE_CONTENT_TYPE_NOSNIFF = True
SECURE_REFERRER_POLICY = "same-origin"
X_FRAME_OPTIONS = "DENY"
```

Three things matter here:

1. **`CSRF_TRUSTED_ORIGINS`** — Django 4+ needs scheme-qualified origins behind
   a proxy; `ALLOWED_HOSTS` alone is not enough and the Django admin login will
   fail with a CSRF error without it.
2. **WhiteNoise** — no nginx sits in front of gunicorn, so Django serves its own
   static files or Swagger UI renders unstyled. It is inserted directly after
   `SecurityMiddleware`, and the spread `**STORAGES` preserves the Cloudinary
   `default` backend from `base.py`.
3. **`SECURE_SSL_REDIRECT` defaults to `False`** — Render already terminates TLS
   and redirects. Leaving Django to redirect as well causes a redirect loop.

## 4. `common/health_views.py` — NEW

```python
"""Health check endpoint for platform probes (Render, Docker, uptime pings).

Kept deliberately cheap: Render polls this frequently, and an expensive check
would waste the free tier's limited CPU. It verifies the database connection
because a live process with a dead database should not be considered healthy.
"""
from __future__ import annotations

import logging

from django.db import connection
from drf_spectacular.utils import OpenApiResponse, extend_schema
from rest_framework import status
from rest_framework.permissions import AllowAny
from rest_framework.response import Response
from rest_framework.views import APIView

logger = logging.getLogger("futsal.health")


class HealthView(APIView):
    """Liveness/readiness probe. Returns 200 when the app can serve traffic."""

    permission_classes = [AllowAny]
    authentication_classes = []

    @extend_schema(
        tags=["internal"],
        summary="Health check",
        description="Returns 200 when the application and database are reachable.",
        responses={
            200: OpenApiResponse(description="Service healthy."),
            503: OpenApiResponse(description="Database unreachable."),
        },
    )
    def get(self, request):
        try:
            with connection.cursor() as cursor:
                cursor.execute("SELECT 1")
                cursor.fetchone()
        except Exception as exc:  # noqa: BLE001 - any DB failure means unhealthy
            logger.error("Health check failed: %s", exc)
            return Response(
                {"success": False, "message": "Service unhealthy.",
                 "errors": {"database": ["Database connection failed."]}},
                status=status.HTTP_503_SERVICE_UNAVAILABLE,
            )
        return Response(
            {"success": True, "message": "Service healthy.",
             "data": {"status": "ok", "database": "ok"}},
            status=status.HTTP_200_OK,
        )
```

It queries the database on purpose: a live process with a dead database must not
report healthy, or Render keeps routing traffic to a broken service.

## 5. `common/cron_views.py` — NEW

Replaces Celery Beat where no scheduler process can run. It calls the **same
service functions** the Celery task calls, so behaviour is identical and the
Celery path keeps working untouched.

```python
"""HTTP cron endpoint for scheduled reminder dispatch.

On hosts where no Celery Beat process can run (free-tier PaaS, serverless), the
periodic reminder dispatch is exposed as an HTTP endpoint that an external
scheduler calls. The work itself is unchanged: this calls the very same service
functions the Celery task calls, so behaviour is identical either way.

Security: the endpoint is public-facing, so it is protected by a shared secret.
Schedulers send ``Authorization: Bearer $CRON_SECRET``. Set the
CRON_SECRET environment variable on the service.
"""
from __future__ import annotations

import hmac
import logging

from django.conf import settings
from drf_spectacular.utils import OpenApiResponse, extend_schema
from rest_framework import status
from rest_framework.permissions import AllowAny
from rest_framework.response import Response
from rest_framework.views import APIView

from common.responses import success_response

logger = logging.getLogger("futsal.cron")


class CronReminderView(APIView):
    """Dispatch due booking reminders. Called by an external scheduler."""

    permission_classes = [AllowAny]
    authentication_classes = []

    def _authorised(self, request) -> bool:
        secret = getattr(settings, "CRON_SECRET", "")
        if not secret:
            # Fail closed: without a configured secret the endpoint stays shut.
            return False
        provided = request.headers.get("Authorization", "")
        expected = f"Bearer {secret}"
        # Constant-time compare so the secret cannot be guessed by timing.
        return hmac.compare_digest(provided, expected)

    @extend_schema(
        tags=["internal"],
        summary="Cron: dispatch due booking reminders",
        description=(
            "Replaces Celery Beat where no scheduler process can run. Requires the "
            "`Authorization: Bearer <CRON_SECRET>` header."
        ),
        responses={
            200: OpenApiResponse(description="Reminders dispatched."),
            401: OpenApiResponse(description="Missing or invalid cron secret."),
        },
    )
    def get(self, request):
        if not self._authorised(request):
            logger.warning("Rejected unauthorised cron request")
            return Response(
                {
                    "success": False,
                    "message": "Unauthorised.",
                    "errors": {"detail": ["Invalid cron credentials."]},
                },
                status=status.HTTP_401_UNAUTHORIZED,
            )

        # Imported lazily so a missing Celery broker never blocks the import.
        from notifications.services import (
            send_automatic_reminder, upcoming_bookings_needing_reminder,
        )

        sent = 0
        failed = 0
        for booking in upcoming_bookings_needing_reminder():
            try:
                if send_automatic_reminder(booking=booking) is not None:
                    sent += 1
            except Exception:  # noqa: BLE001 - one bad booking must not stop the run
                failed += 1
                logger.exception("Reminder failed for booking %s", booking.pk)

        logger.info("cron reminders sent=%d failed=%d", sent, failed)
        return success_response(
            data={"sent": sent, "failed": failed},
            message="Reminder dispatch completed.",
        )

    @extend_schema(
        tags=["internal"],
        summary="Cron: dispatch due booking reminders (POST alias)",
        request=None,
        responses={
            200: OpenApiResponse(description="Reminders dispatched."),
            401: OpenApiResponse(description="Missing or invalid cron secret."),
        },
    )
    def post(self, request):
        """Schedulers issue GET; POST is allowed for manual curl triggers."""
        return self.get(request)
```

Design points worth preserving:

- **Fails closed.** An unset `CRON_SECRET` rejects everything, so a
  misconfigured deploy cannot leave a public trigger exposed.
- **`hmac.compare_digest`** avoids a timing side-channel on the secret.
- **Per-booking `try`** so one bad record cannot abort the whole run; failures
  are counted and reported in the response.

## 7. `render_build.sh` — NEW

```bash
#!/usr/bin/env bash
# Render build step. Runs on every deploy, before the start command.
set -o errexit   # abort the deploy if any step fails

pip install --upgrade pip
pip install -r requirements.txt
```


`set -o errexit` matters: without it a failed migration would still deploy,
leaving the code running against an older schema.

```yaml
  #   runtime: python
  #   plan: starter            # background workers have no free plan
  #   region: singapore
  #   branch: main
  #   buildCommand: "pip install -r requirements.txt"

  #   name: futsal-celery-beat

  #   plan: starter
  #   region: singapore
  #   branch: main
  #   buildCommand: "pip install -r requirements.txt"
  #   startCommand: "celery -A config beat --loglevel=info"
  #   envVars:
  #     - fromGroup: futsal-shared

# --------------------------------------------------------------- database
# Render's free Postgres is deleted when it expires. Use Neon (free, no expiry)
# and set DATABASE_URL by hand. Uncomment only on a paid plan:
#
# databases:
#   - name: futsal-db
#     plan: basic-256mb
#     region: singapore
```

Decisions encoded here:

- **`healthCheckPath: /healthz/`** — Render rolls back a deploy that never
  becomes healthy.
- **No `databases:` block** — Render's free Postgres expires and is deleted;
  `DATABASE_URL` points at Neon instead.
- **Worker blocks commented out** — Render background workers have no free tier.
- **`generateValue: true`** for `SECRET_KEY` / `CRON_SECRET`, so real secrets are
  never committed.
- **`--workers 2 --threads 4`** fits the free tier's 512 MB. More workers will
  trigger an out-of-memory restart loop.

```python
"""Serverless cron endpoint (replaces Celery Beat on Vercel)."""
from __future__ import annotations

import datetime as dt

import pytest

from bookings.services import create_booking
from common.enums import PaymentStatus
from common.utils import local_now
from futsal.models import Slot

pytestmark = pytest.mark.django_db

URL = "/api/v1/internal/cron/reminders/"


@pytest.fixture
def booking_in_one_hour(futsal, user, monkeypatch):
    """A paid booking starting in ~58 minutes, clock pinned to midday."""
    frozen = local_now().replace(hour=12, minute=0, second=0, microsecond=0)
    monkeypatch.setattr("notifications.services.timezone.now", lambda: frozen)
    start = frozen + dt.timedelta(minutes=58)
    slot = Slot.objects.create(
        futsal=futsal, date=start.date(),
        start_time=start.time().replace(second=0, microsecond=0),
        end_time=(start + dt.timedelta(hours=1)).time().replace(second=0, microsecond=0),
    )
    monkeypatch.setattr("bookings.services.local_now", lambda: frozen - dt.timedelta(hours=1))
    monkeypatch.setattr("futsal.models.local_now", lambda: frozen - dt.timedelta(hours=1))
    return create_booking(slot_id=slot.id, full_name="Cron User",
                          email="cron@example.com", phone_number="9800000077",
                          user=user, payment_status=PaymentStatus.PAID)


def test_cron_requires_secret(api, settings):
    settings.CRON_SECRET = "s3cret"
    assert api.get(URL).status_code == 401


def test_cron_rejects_wrong_secret(api, settings):
    settings.CRON_SECRET = "s3cret"
    assert api.get(URL, HTTP_AUTHORIZATION="Bearer nope").status_code == 401


def test_cron_accepts_correct_secret(api, settings):
    settings.CRON_SECRET = "s3cret"
    response = api.get(URL, HTTP_AUTHORIZATION="Bearer s3cret")
    assert response.status_code == 200
    assert response.data["data"] == {"sent": 0, "failed": 0}


def test_cron_fails_closed_when_no_secret_configured(api, settings):
    """An unset CRON_SECRET must lock the endpoint, never open it."""
    settings.CRON_SECRET = ""
    assert api.get(URL, HTTP_AUTHORIZATION="Bearer anything").status_code == 401
    assert api.get(URL).status_code == 401


def test_cron_sends_due_reminder_and_dedups(api, settings, booking_in_one_hour):
    from django.core import mail

    settings.CRON_SECRET = "s3cret"
    first = api.get(URL, HTTP_AUTHORIZATION="Bearer s3cret")
    assert first.data["data"]["sent"] == 1
    assert len(mail.outbox) == 1
    second = api.get(URL, HTTP_AUTHORIZATION="Bearer s3cret")
    assert second.data["data"]["sent"] == 0
```

The fixture pins the clock to midday: a time-relative booking created late in
the evening would roll past midnight and violate the `slot_start_before_end`
constraint, making the test fail only at certain hours.

## What must NOT change

`config/celery.py`, `notifications/tasks.py`, the Beat schedule, `Dockerfile` and
`docker-compose.yml` stay exactly as they are. The cron endpoint is an
**additional** trigger, not a replacement — so the same codebase runs on Render
free (external cron), Render paid (real Celery), or Docker.
